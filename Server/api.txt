1. ABOUT MODULE
================================================================================
Base URL: /about
Base Server URL: http://localhost:<PORT>/about (or your production domain)

--------------------------------------------------------------------------------
1.1 GET ABOUT DETAILS
--------------------------------------------------------------------------------
Description: Retrieves the About section information (served from Redis cache if available, otherwise MongoDB).
Access: Public (No Authentication Required)

[REQUEST]
• Method: GET
• Endpoint: /about
• Headers:
    Accept: application/json

[RESPONSES]
• 200 OK (Success - Cached or Database):
    {
      "data": {
        "_id": "664f1c9d2f8a1a001e3b4c12",
        "content": "Hello! I am a Full Stack Developer specializing in TypeScript, Node.js, Express, and React...",
        "createdAt": "2026-01-15T10:00:00.000Z",
        "updatedAt": "2026-02-01T12:30:00.000Z",
        "__v": 0
      },
      "source": "cache" // or "database"
    }

• 404 Not Found:
    {
      "message": "About information not found"
    }

• 500 Internal Server Error:
    {
      "message": "Internal server error"
    }

--------------------------------------------------------------------------------
1.2 UPDATE ABOUT DETAILS
--------------------------------------------------------------------------------
Description: Updates About content. Queues update job to BullMQ worker, invalidates/updates Redis cache, and triggers notification.
Access: Protected (Requires Admin Cookie: 'admin')

[REQUEST]
• Method: PUT
• Endpoint: /about
• Headers:
    Content-Type: application/json
    Accept: application/json
• Cookies / Credentials:
    admin=<jwt_token> (Include credentials: "include" / withCredentials: true)
• Body (JSON):
    {
      "content": "Updated about section content describing experience, background, and tech stack."
    }

[VALIDATION RULES]
• content: Required string, minimum length 1 character.
• strict schema: Disallows extraneous unknown fields.

[RESPONSES]
• 200 OK (Success):
    {
      "message": "About updated successfully"
    }

• 400 Bad Request (Validation Error):
    {
      "message": [
        {
          "code": "too_small",
          "minimum": 1,
          "type": "string",
          "inclusive": true,
          "exact": false,
          "message": "Content is required",
          "path": ["content"]
        }
      ]
    }

• 403 Forbidden (Missing admin cookie):
    {
      "success": false,
      "message": "Access denied. Admin cookie is missing."
    }

• 401 Unauthorized (Invalid / Expired token):
    {
      "success": false,
      "message": "Invalid admin cookie. Authentication failed."
    }

• 500 Internal Server Error:
    {
      "message": "Internal server error"
    }

--------------------------------------------------------------------------------
ABOUT MODULE - FRONTEND INTEGRATION PROMPT
--------------------------------------------------------------------------------
"Implement frontend services/hooks for the About module:
1. Fetch About: Call `GET /about` to display the about details (`data.content`). Handle loading, empty state (404), and error states.
2. Edit About (Admin): Call `PUT /about` with payload `{ content: string }` and credentials enabled (`withCredentials: true` / `credentials: 'include'`). On 200 OK, show success toast and invalidate cache/refetch query. Handle 400 validation, 401/403 authorization, and 500 errors."

Base URL: /auth

--------------------------------------------------------------------------------
2.1 SIGNUP (REGISTER ADMIN)
--------------------------------------------------------------------------------
Description: Creates a new admin account with hashed password.
Access: Public

[REQUEST]
• Method: POST
• Endpoint: /auth/signup
• Headers:
    Content-Type: application/json
    Accept: application/json
• Body (JSON):
    {
      "name": "Pratik Rathod",
      "email": "admin@example.com",
      "password": "strongPassword123"
    }

[VALIDATION RULES]
• name: Required string, minimum 2 characters.
• email: Required valid email address.
• password: Required string, minimum 6 characters.
• strict schema.

[RESPONSES]
• 201 Created (Success):
    {
      "success": true,
      "message": "Account created successfully",
      "user": {
        "id": "664f1c9d2f8a1a001e3b4c10",
        "email": "admin@example.com",
        "FirstName": "Pratik",
        "LastName": "Rathod"

• 400 Bad Request (Validation failure or User already exists):

      "error": "User already exists" // or validation error message

• 500 Internal Server Error:
    {
      "error": "Internal Server Error"
    }

2.2 LOGIN
--------------------------------------------------------------------------------
Description: Authenticates admin credentials, sets an HTTP-only 'admin' cookie (1-day expiry), and returns user details + JWT token.
Access: Public

[REQUEST]
• Method: POST
• Endpoint: /auth/login
• Headers:
    Content-Type: application/json
    Accept: application/json
• Body (JSON):
    {
      "email": "admin@example.com",
      "password": "strongPassword123"
    }

[VALIDATION RULES]
• email: Required valid email address.
• password: Required string, min 1 character.
• strict schema.

[RESPONSES]
• 200 OK (Success):
    Set-Cookie: admin=<jwt_token>; HttpOnly; Path=/; Max-Age=86400; SameSite=Lax (or None in production)
    {
      "message": "Login successful",
      "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "user": {
        "id": "664f1c9d2f8a1a001e3b4c10",
        "email": "admin@example.com",
        "FirstName": "Pratik",
        "LastName": "Rathod"
      }
    }

• 400 Bad Request (Account not found or Invalid password):
    {
      "error": "Account not found" // or "Please enter valid Password"
    }

• 500 Internal Server Error:
    {
      "error": "Internal Server Error"
    }

--------------------------------------------------------------------------------
AUTH MODULE - FRONTEND INTEGRATION PROMPT
--------------------------------------------------------------------------------
"Implement frontend authentication flow with Axios / React Context:

1. Setup Axios Client:
   - Configure `axios.create({ baseURL: '...', withCredentials: true })` to always send/receive HTTP-only cookies.

2. Auth Context & State:
   - On app mount, call `GET /auth/check` to verify active session and store `user` object in AuthContext.
   - Login Handler: Call `POST /auth/login` with `{ email, password }`. On success, set user in state and redirect to admin dashboard.
   - 2FA/Login OTP Handler: If 2FA enabled, call `POST /auth/login-verify` with `{ email, otp }`.
   - Logout Handler: Call `GET /auth/logout`, clear user state from context, and redirect to login page.

3. Forgot & Reset Password Multi-Step Flow:
   - Step 1: Call `POST /auth/forgot-password` with `{ email }` to send OTP.
   - Step 2: Call `POST /auth/verify-otp` with `{ email, otp }` to validate the 6-digit code.
   - Step 3: Call `POST /auth/reset-password` with `{ email, password }` to save the new password and navigate to login.

4. Error & Feedback Handling:
   - Display toast/alert for `error` messages from backend responses (400, 401, 403, 404, 500)."

[VALIDATION RULES]
• title: Required string, min 1 character.
• slug: Required string, min 1 character (lowercase, unique).
• excerpt: Required string, min 1 character.
• content: Required string, min 1 character.
• tags: Array of strings or comma-separated string or JSON string array.
• isPublished: Boolean or string boolean ("true"/"false").
• file / image: Valid image file (JPEG, PNG, WEBP).
